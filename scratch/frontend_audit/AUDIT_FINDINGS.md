# AUDIT FINDINGS

1. **server.py::_init_evaluation_results() initializes comparison conditions with 50,000 hardcoded outcomes**
   - **CONFIRMED**: `server.py`, line 193-202. `tp=20000, fn=5000, fp=0, tn=25000`.
   - **Visibility**: Manifests as exactly 100.00% Precision, 80.00% Recall in the live dashboard before traffic streams.

2. **The research scraper derives “evasions prevented” using int(recall_difference * 50000)**
   - **CONFIRMED**: `scratch/scrape_research_repo.py`, line 78. `evasions = int(diff_r * 50000)`.
   - **Visibility**: Results Summary shows "6465 evasions prevented" based on this fake extrapolation.

3. **results.js substitutes numerical fallback results when comparison data is absent**
   - **CONFIRMED**: `frontend/results.js`, line 849. `if (!useLiveBenchmark) { matrix = STATIC_C1_C7_MATRIX; }`.

4. **get_evaluation_results() contains predetermined “best defense”, batch-count, zero-FPR**
   - **CONFIRMED**: `server.py`, line 255. `best_def = "FS"`. FPR is hardcoded `0.0000` in initial matrices.

5. **Historical research results, current live measurements mixed or mislabeled**
   - **CONFIRMED**: "Compute Live Benchmark" toggle swaps between scraper-averaged historical JSONs and the live mock metrics seamlessly.

6. **Base and Recall-Aware comparisons may not use genuinely separate inference paths**
   - **CONFIRMED**: Both paths in `server.py` utilize the exact same feature extraction and `DefenseArm` simulation loop logic, relying on a unified controller threshold instead of fully isolated pipelines.

7. **C1–C7 labels and actual runtime configurations disagree**
   - **CONFIRMED**: `server.py` `get_base_intensity()` has hardcoded floats (`afp=0.00030`, `fs=2.0`), entirely ignoring `.research_repo/configs/defenses.yaml`.

8. **Query traffic, mode changes incorrectly affect comparison metrics**
   - **UNVERIFIABLE**: Static audit limits execution of comprehensive API integration tests across state transitions.

9. **Tables, charts, summaries use different sources**
   - **CONFIRMED**: Charts use `Math.random()`, tables use `get_evaluation_results()` (live) or `STATIC_C1_C7_MATRIX` (static).

10. **FS displayed decimal precision disagree with actual implementation**
    - **CONFIRMED**: `server.py`, line 218. `d_val = int(round(val))`. Formatting uses float, execution rounds to integer.

11. **Primary vs Sensitivity Result Mixing**
    - **CONFIRMED**: The current `STATIC_C1_C7_MATRIX` was generated by a script that indiscriminately averaged all `run_summary.json` files together, failing to adhere to the rigid pooling and weighting defined in `phase11c_rq3_statistical_decisions.csv` and `phase11c_rq1_base_performance.csv`.

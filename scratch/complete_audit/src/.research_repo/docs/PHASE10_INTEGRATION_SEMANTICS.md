# Phase 10 Integration Semantics

## 1. Evaluation Roles
Measurement and crafting datasets are obtained via exact validated joins against `evaluation_roles.csv` and `evaluation_batches.csv` using `eval_position`. The runner strictly demands:
- 18,000 crafting identities
- 72,000 measurement identities
- 144 batches of 500 records
Missing, duplicate, or cross-role identities produce an explicit `ValueError`.

## 2. Attack Definitions
- **Silent Probing**: No attack applied. True negatives and true positives remain.
- **Surrogate Transfer**: Uses only crafting pool. Measurement candidate generated by surrogate.
- **Decision-Boundary**: Uses 50-query limit. Tests exactly 200 eligible target samples over the full 72,000 measurement pool.

## 3. Policy Execution
Base defense runs using the `FixedIntensityPolicy` without rolling state, whereas Recall-Aware uses `RecallAwareController`. All states are reset via `.reset()` strictly between independent combinations of seed, config, defense, and attack.

## 4. Score Exposure
Average precision is supported through a probability interface exposing `predict_proba()[:, 1]` for AFP and FS, and `positive_votes / 11` for RS. This probability exposure strictly avoids leakage to the attack generators, which are only provided with hard decisions.

## 5. Artifact writing
Each run operates atomically. A log writes to a `.tmp` file which is renamed upon successful completion to maintain provenance and atomic execution.

## 1. Executive Summary & Audit Revisions

Following an in-depth source and binary inspection of `ids_runtime_audit.zip` (including `server.py`, `attacker_sim.py`, `run.py`, defense modules, attack algorithms, controllers, and `runtime_package/model/frozen_rf.joblib`), a critical correctness defect was identified:
- **The Feature-Vector Inversion Defect**: `server.py` previously checked `sample_id` before `feature_vector`. Because `attacker_sim.py` transmitted both `sample_id` (for dataset provenance) and `feature_vector` (the candidate $X_{\text{adv}}$ generated by the black-box attack algorithm), the server discarded $X_{\text{adv}}$ and re-evaluated the unperturbed sample from `X_demo[sample_id]`. Consequently, the attack algorithms were not actually testing their generated vectors against the protected IDS.

**Remediation & Current State:**
1. **Precedence Inversion Fixed**: `server.py` now prioritizes `req.feature_vector`. When provided, that exact 78-element vector is evaluated by the defense and Random Forest. `sample_id` is retained strictly for dataset provenance and traffic-family attribution.
2. **Server-Side Provenance Enforced**: The server derives `traffic_family` from dataset metadata only when `sample_id` is a valid dataset index. Synthetic or non-dataset vectors are strictly attributed as `Unknown` (`Synthetic / Non-dataset`), preventing client-side metadata spoofing.
3. **Genuine Adversarial Evasion Test**: Test C was rewritten to discard the previous benign-sample label flip. It now runs a real attack sample (`sample_id: 10`, `DoS attacks-SlowHTTPTest`) perturbed via `DecisionBoundaryAttack` bisection into the benign prediction region, successfully proving adversarial evasion (`ids_classification: Benign`, `is_attack: True`, `HTTP 200 OK`).
4. **RS Confidence Semantics**: Randomized Smoothing now reports the empirical positive vote fraction of the noise ensemble (`vote_frac[0]`) rather than a hardcoded `0.95 / 0.05` placeholder.
5. **Controller C1 Configuration & Cadence**: `runtime_package/run.py` was updated to read `c_cfg["controller_configurations"]["C1"]` (eliminating fallback to incorrect default parameters) and aligned to batch observations every 5 attack decisions.

## 3. Authoritative Random Forest & Feature Schema

### A. Authoritative Model (`runtime_package/model/frozen_rf.joblib`)
- **Format**: Joblib serialized `sklearn.ensemble.RandomForestClassifier`.
- **Architecture**: 200 decision trees, trained on CSE-CIC-IDS2018.
- **Input Dimension**: Exactly 78 numerical flow features.
- **Output Classes**: Strictly binary: `[0, 1]` ($0 \to \text{Benign}$, $1 \to \text{Attack}$).
- **Authoritative Decision**: The model never outputs multiclass labels (`DDoS`, `Bot`, `Silent Probing`, etc.). Any category other than `Attack` or `Benign` displayed on the dashboard originates from dataset provenance metadata or session state, never from the Random Forest classifier.

### B. Legacy 77-Feature Artifacts (Clarification)
- The repository root contains legacy prototype files in `models/` (`rf_ids_cic.pkl.xz`, `X_bounds_cic.json`, `X_ref_cic.json`) referencing a 77-feature configuration from early repository scaffolding.
- **Authoritative Directive**: The active application and `runtime_package/` exclusively use the 78-feature pipeline (`frozen_rf.joblib`, `feature_names.json`, `feature_mask.json`, `training_bounds.parquet`). The legacy 77-feature files in `models/` are completely bypassed by `server.py` and `run.py`.

## 5. Defenses & Recall-Aware Feedback Controller

### A. Defense Implementations
- **Adaptive Feature Poisoning (AFP)** (`runtime_package/defenses/afp.py`):
  Adds deviation-scaled bounded noise scaled by intensity $\varepsilon$ and step size $\alpha = 0.5$ across the 63 modifiable features (leaving 15 protected features untouched), clipped to training bounds. It does **not** project flows toward a benign centroid.
- **Randomized Smoothing (RS)** (`runtime_package/defenses/randomized_smoothing.py`):
  Injects Gaussian noise $\mathcal{N}(0, \sigma^2)$ into modifiable features across an ensemble of 11 noise samples (configured in `defenses.yaml`). Confidence is reported as the empirical positive vote fraction.
- **Feature Squeezing (FS)** (`runtime_package/defenses/feature_squeezing.py`):
  Quantizes continuous modifiable features into discrete bins (intensity $d = 2$).

### B. Controller State Machine & Transition Rules (C1)
The Recall-Aware Controller C1 (`runtime_package/configs/controllers.yaml`) implements the feedback loop:
- **Rolling Recall Formula**:
  $$\text{Recall}_{\text{rolling}} = \frac{\sum \text{TP}_{\text{window}}}{\sum \text{TP}_{\text{window}} + \sum \text{FN}_{\text{window}}}$$
- **Thresholds**: $R_{\text{critical}} = 0.85$, $R_{\text{min}} = 0.95$.
- **Batch Window**: In this interactive demonstration, evaluated after every 5 labeled attack decisions (`window_size = 5`). Note: This is an interactive demo cadence; the formal research protocol used a window of 5 completed batches (500 flows/batch).
- **State Machine Transitions**:
  1. **Red State** ($\text{Recall} < 0.85$): Critical detection degradation. Defense intensity is aggressively decayed via `fast_decay = 0.40` ($\varepsilon_{t+1} = \varepsilon_t \times 0.40$) to restore detection fidelity.
  2. **Yellow State** ($0.85 \le \text{Recall} < 0.95$): Warning zone. Defense intensity is moderately decayed via `slow_decay = 0.90` ($\varepsilon_{t+1} = \varepsilon_t \times 0.90$).
  3. **Green State** ($\text{Recall} \ge 0.95$): Healthy detection. Defense intensity is grown/restored via `growth_factor = 1.05` ($\varepsilon_{t+1} = \varepsilon_t \times 1.05$).
  4. **Intensity Clamping**: Output is clamped to $[\text{intensity\_min}, \text{intensity\_max}]$.

### C. Calibration Bounds & Intensity Ceiling
- In `runtime_package/configs/defenses.yaml`:
  `epsilon_base: 0.0003`, `intensity_min: 0.0`, `intensity_max: 0.0003`.
- **Operational Reality**: Because $\text{intensity\_max} = 0.0003$, applying `growth_factor = 1.05` when intensity is at base ($0.0003$) yields $0.000315$, which is clamped back to $0.0003$.
- **Design Rationale**: This is the intended behavior of the frozen Phase 8 calibration protocol. The base intensity represents the maximum calibrated perturbation allowed without corrupting network flow utility. Thus, the Green growth rule functions to *recover* defense intensity back toward $0.0003$ after defensive decay during a low-recall episode, rather than growing unboundedly beyond the calibrated maximum.

## 6. Crucial Research Caveats & Real-World Distinctions

For complete academic rigor and thesis defensibility, the following distinctions are formally recorded:

1. **Flow-Feature IDS vs Raw Packet Inspection**:
   - The Random Forest requires exactly 78 numeric flow features (e.g., flow duration, packet length statistics, inter-arrival times).
   - The runtime package does not contain a raw packet capture sniffer (PCAP / Libpcap) or an online CICFlowMeter feature extractor.
   - The platform is an empirical flow-feature IDS runtime demonstration, evaluating structured flow vectors.
2. **Recall Tracking Semantics in Simulation vs Online Deployment**:
   - In live online network operations, ground truth labels are rarely available immediately.
   - In this demonstration, the Recall-Aware controller receives post-decision ground-truth feedback via the simulation harness (`req.is_attack`).
   - The platform is appropriately described as a *controlled research demonstration runtime with simulation feedback*, rather than an autonomous production IDS with clairvoyant online recall discovery.
3. **Randomized Smoothing Confidence**:
   - RS confidence represents the ensemble majority vote fraction ($\frac{\text{positive votes}}{\text{total noise samples}}$), reflecting certification consensus rather than standard Random Forest posterior class probability.
